🔍 Current System Analysis

✅ What Exists Today

  • Drivers managed with user accounts, documents, and status
  • Trips assigned to drivers with embedded vehicle info
  • Vehicle info embedded in driver model (vehicle_type, vehicle_number)
  • Role-based access control system

❌ Problems with Current Approach

  • ⚠️ Vehicles are tied to drivers (1:1 relationship)
  • ⚠️ Cannot track vehicle maintenance history
  • ⚠️ Cannot assign different vehicles to same driver
  • ⚠️ No vehicle availability tracking
  • ⚠️ Cannot manage spare/pool vehicles
  • ⚠️ No vehicle documentation (insurance, RC, etc.)

💡 Proposed Solution

Core Concept

Vehicles become independent entities that can be:

  • Assigned to drivers (many-to-many relationship)
  • Tracked independently with their own lifecycle
  • Managed with their own documents and status
  • Analyzed for utilization and maintenance

⚡ Electric Vehicle Charging Monitoring

📝 Charging Session - User Input Requirements

When a driver completes a charging session, they must enter these 5 REQUIRED fields:

1
Start SOC (%)
Battery State of Charge when charging started (e.g., 15%)
2
End SOC (%)
Battery State of Charge when charging ended (e.g., 85%)
3
kW Consumed
Energy consumed in kilowatt-hours (e.g., 42 kWh)
4
Amount
Total cost paid in rupees (e.g., ₹336)
5
Charging Station Name
Name and location (e.g., "Tata Power, MG Road, Bangalore")

🔄 Auto-Calculated Fields

  • SOC Charged = End SOC - Start SOC (e.g., 70%)
  • Cost per kWh = Amount ÷ kW Consumed (e.g., ₹8.00/kWh)
  • Duration = End Time - Start Time (e.g., 1h 15m)

Charging Session Workflow

Step 1: Driver clicks "Start Charging" button
Step 2: App records start time automatically
Step 3: Vehicle is charging (timer running)
Step 4: Driver clicks "End Charging"
Step 5: Driver enters 5 required fields
Step 6: System auto-calculates SOC charged & cost/kWh
Step 7: Session saved to database
Step 8: Data available for analytics & reports ✓

🗄️ Database Collections

1. vehicles

Purpose: Store all vehicle information

2. vehicle_assignments

Purpose: Track vehicle-driver assignments

vehicle_id driver_id assigned_at assignment_type status

3. vehicle_maintenance

Purpose: Track all maintenance activities

4. vehicle_expenses

Purpose: Track all vehicle-related expenses

Purpose: Track all EV charging sessions

Purpose: Monitor battery degradation over time

battery_health_% charging_cycles actual_capacity degradation_rate
